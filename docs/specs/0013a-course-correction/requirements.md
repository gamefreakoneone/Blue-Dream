# 0013a Course Correction Requirements

## Goal

Spec 0013 shipped a working PWA, but live phone testing on July 19 surfaced five experience problems that must be corrected before the July 20 demo. This spec is a **targeted course correction on the 0013 surfaces only** — small, demo-safe edits, no rewrites, no new dependencies.

The five problems, in priority order:

1. **The chat agent does not know it can set reminders.** Reminder creation currently happens in a fire-and-forget post-turn extraction task, so the reminder is created silently while the *reply* refuses ("I'm sorry, I can't set timed reminders" — evidence: `Proof/spec-0013/Screenshot_20260719_230948_Chrome.jpg`, where the refused laundry reminder nonetheless appears on the Reminders tab). The agent must create reminders synchronously inside the query flow and confirm them in its reply with the real details.
2. **The Reminders tab is form-heavy.** Two manual create forms dominate the screen. The patient-facing tab must be list-only: each reminder card offers **Done** and **Remove**. Chat is the creation path. Additionally, marking a *daily* reminder done from the tab permanently archives it — it must instead complete today's occurrence and roll forward to tomorrow.
3. **Acknowledging a safety warning does not clear the Safety tab.** The chat safety bubble only acks the proactive *message*; the underlying alert stays `open` forever and the Safety tab never refreshes. Safety bubbles must offer an explicit "I'm okay" action that acknowledges the underlying alert, and the Safety tab must pick the change up on its own.
4. **"New chat" is buried in the demo-tools sheet.** A visible new-conversation button belongs in the top bar.
5. **"Your days" on Memories is a flat room-by-room summary list.** Replace it with one warm narrative card per day ("Yesterday: …"), generated by the LLM from that day's material and cached.

Superseded by the 2026-07-20 spec 0008 corrective amendment: the UI already rendered a stored highlighted screenshot correctly, but the upstream selector was kitchen-specific and could return no target or a substring false positive before spatial grounding. The room-agnostic observation/judgment/targeting fix lives in spec 0008; the 0013a UI remains unchanged.

## Functional Requirements

### R1 — Reminder intent in the query router

- The Jeeves router gains a fifth intent, `reminder`, chosen only when the user explicitly asks to be reminded / to set, create, or schedule a reminder. Questions about whether something already happened (e.g. "did I take my medicine today?") are never `reminder`.
- A new reminder handler runs **synchronously inside `POST /query`**: one structured extraction call (reusing the existing `ReminderExtraction` model and the extraction prompt rules — relative times resolved in the project timezone, explicitly morning-ish event requests default to the 06:00–11:00 window, and event reminders with **no stated time constraint default to the full day, 00:00–23:59** — the window is a required matcher field, and a fabricated narrow window silently drops out-of-window events), then `create_reminder(source="chat", origin_context={session_id, created_from_text})`.
- The reply text is a **deterministic confirmation template** (no second LLM call): time reminders confirm text + friendly due phrasing (today / tomorrow / weekday, local time) and mention daily repetition when applicable; event reminders confirm text + the noticed condition. On extraction returning `is_reminder=false`, fall through to the general handler (router-misfire safety net). On any failure, return a warm fixed message — never raw exception text.
- The general handler's prompt states the assistant *can* set reminders, so a routing miss never produces another on-camera refusal.
- `POST /query` gains a `session_id` pass-through into the query flow for `origin_context`; the request/response contract is unchanged.
- The post-turn extraction keeps profile facts but **loses its reminder branch entirely** (no double-creation path).

### R2 — Reminders tab list-only + completion semantics

- `RemindersScreen` removes both create forms (time and event). Manual creation remains possible via `POST /reminders` (curl/scripted demo setup) — intentionally no form anywhere in the patient UI, including the demo-tools sheet; the chat intent is the product's creation path.
- Each reminder card offers **Done** and a quieter **Remove**.
- `POST /reminders/{id}/done` (patient mode): a daily time reminder completes today's occurrence — `due_at` rolls forward, the reminder stays `active` (and visibly moves to "Later" in the UI). One-shot and event reminders archive as today. Delivery-mode behavior is untouched.
- New endpoint `POST /reminders/{id}/archive` → `{"ok": true}` / 404. Archive, never delete (memories are archived, never erased); the UI labels it "Remove".

### R3 — Safety acknowledgement sync

- `GET /proactive/pending` items additionally expose `related_id` (additive field; for safety messages this is the alert id).
- Safety proactive bubbles render an explicit **"I'm okay"** button that calls the existing `POST /alerts/{alert_id}/ack` with `{"action": "ok"}`, then shows a soft confirmation line. The existing render-time auto-ack of the proactive *message* is unchanged.
- The Safety tab refreshes itself: refetch on every visit (screen mount) plus a modest poll (~30s) while visible, so an alert acknowledged from chat disappears without a manual reload.

### R4 — Visible new-chat control

- The top bar gains a new-conversation icon button next to the gear, wired to the existing conversation-reset flow (reset endpoint + session rotation + fresh thread + navigate to Chat). The demo-tools sheet entry stays.

### R5 — Daily digest ("Your days" → "Your story")

- New endpoint `GET /memory/digest?days=` (default 7, max 31; optional `force` regeneration flag) returning newest-first, JSON-safe day digests: `{digest_id, date, text, highlights, source_summary_count, source_event_count, created_at, updated_at}`.
- Per local day the digest synthesizes **both** that day's `memory_summaries` **and** that day's active raw events (importance-sorted, capped) — the event path is mandatory because consolidation lags recent days. Days with no material produce no card.
- One structured LLM call per uncached day: warm, patient-facing, 2–4 short sentences plus up to 3 short highlights; never mentions cameras, monitoring, or databases; never invents details.
- Results are cached in a new `memory_digests` Mongo collection keyed by date with a source fingerprint; unchanged sources mean zero LLM calls on reload. A failed generation falls back to the stale cached digest or omits the day — the endpoint never fails wholesale because one day errored.
- `MemoriesScreen` replaces the per-room summary list with one card per day (Today / Yesterday / weekday labels), digest text, optional highlights, and a "moments remembered" footer. The profile-facts section is unchanged.
- `GET /memory/summaries` is untouched (spec 0012 contract).

## Technical Constraints

- Preserved contracts untouched: `POST /query` request/response shape, `POST /conversation/reset`, all alert endpoints, all geofence endpoints, `/proactive/*` semantics (the atomic pending→delivered claim; the only change is the additive `related_id` field), `POST /devices/register`, `/storage` + `/capture` mounts, `GET /memory/summaries`.
- No new Python or npm dependencies expected; if one becomes unavoidable, pin it in the same change.
- All structured LLM calls go through the shared JSON-hardening path. No raw exception text patient-facing.
- MongoDB stays the source of truth; `memory_digests` is a rebuildable cache.
- Existing pytest suite (143 tests) stays green; new behavior gets mocked-LLM tests. `npm run build` stays clean.
- **This spec is validated but not committed in the implementation run** — the working tree is left uncommitted for on-device review; commits happen manually afterward. This is an explicit, documented deviation from the per-phase commit rule.

## Non-Requirements

- No weekly recurrence (daily-only stays; explicitly decided).
- No LLM-based detection of conversational safety acknowledgement (the deterministic button is the shipped path).
- No reminder create form anywhere in the UI, including demo tools.
- No changes to spec 0009 (voice), the push chain, PWA install flow, or any 0013 surface this spec does not name.
- No reworking of the morning-report proactive message (it already exists and complements the digest).

## Acceptance Criteria

1. Chat: "Remind me to take my pills at 9pm" gets a reply that confirms the reminder with its actual text and time, and the reminder appears on the Reminders tab with `source: "chat"`. "Did I take my medicine today?" is not routed to `reminder`.
2. Reminders tab shows no forms. Done on a daily reminder keeps it listed with `due_at` rolled forward; Done on a one-shot removes it; Remove archives any reminder.
3. A safety proactive bubble shows "I'm okay"; tapping it acknowledges the underlying alert and the Safety tab no longer lists it after its next refresh — with no manual reload.
4. The top-bar new-chat button starts a fresh conversation from any tab.
5. Memories shows one narrative card per day, newest first, reading as a warm recap (not room reports); a second load of `GET /memory/digest` serves from cache with zero LLM calls; `GET /memory/summaries` still returns its 0013 shape.
6. `python -m pytest tests/` fully green (143 existing + new); `npm run build` clean; `git status` shows only uncommitted working-tree changes (zero new commits).
